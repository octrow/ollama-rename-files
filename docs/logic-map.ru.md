# Карта логики

Как папка с плохо названными файлами превращается в те же файлы с именами по содержимому.
Карта описывает код как он есть сейчас, шаг за шагом.
Каждый шаг говорит, что он решает, где поток ветвится и какой модуль это делает.

Зеркало `docs/logic-map.md`, ниже по приоритету: при расхождении прав английский файл.
Известные пробелы и исправления — в `docs/plans/2026-11-01-logic-map-fixes.md`.

Правило: меняешь шаг или ветку — правишь `docs/logic-map.md` и этот файл в том же коммите.
`tests/test_logic_map.py` проверяет, что каждая строка `Module:` указывает на настоящий модуль.

## Поток целиком

```
папка + шаблон + модель
  │
  ├─ 1  Развилка ............. CLI или GUI?
  ├─ 2  Настройка ............ какие папка, шаблон, модель, длина контекста?
  ├─ 3  Поиск шаблонов ....... какие группы (префикс, расширение) есть в папке?
  ├─ 4  Отбор файлов ......... какие файлы будут переименованы?
  ├─ 5  Папка бэкапа ......... куда идут оригиналы?
  ├─ 6  Чтение содержимого ... какой текст увидит модель?
  ├─ 7  Запрос к модели ...... какое имя предлагает Ollama?
  ├─ 8  Очистка ответа ....... какая часть ответа — имя?
  ├─ 9  Санитайз ............. какое безопасное имя файла?
  ├─ 10 Бэкап и переименование  копия оригинала, переименование в свободное имя
  └─ 11 Цикл и отчёт ......... в каком порядке и что видит пользователь
  │
переименованные файлы + backup_<timestamp>/ + сводка
```

Ничего не рекурсивно: находятся, отбираются и переименовываются только файлы прямо в папке.

## Где поток делится по типу файла

Реестра нет: решают суффикс файла и первые байты, в трёх местах.

| Вариант | Чем включается | Шаги | Что меняется |
|---|---|---|---|
| PDF | суффикс `.pdf`, любой регистр | 6 | текстовый слой через pypdf вместо байтов; пустой текст → файл падает |
| Бинарный или UTF-16 | байт NUL в первых `контекст × 4` байтах | 6 | файл падает, «only UTF-8 text and PDF files are supported» |
| Текст | любой другой файл | 6 | строгое декодирование UTF-8; неверные байты → файл падает с ошибкой кодека |
| Расширение | `Path.suffix` оригинала | 3, 4, 9 | поиск группирует по последнему суффиксу в нижнем регистре; отбор — `name.lower().endswith(ext.lower())`; пустое расширение у выбранного шаблона и в CLI — «без расширения», в поле GUI, введённом вручную, — «любое»; новое имя сохраняет суффикс оригинала, расширение от модели отбрасывается |

Примеры:
- `report.PDF` с текстовым слоем → путь PDF, имя `<slug>.PDF`.
- `scan.pdf` без текста → падает с «PDF has no text layer (scanned image?)».
- `notes.txt` в cp1251 → падает с «'utf-8' codec can't decode byte …».

Module: `rename_files`

## Точки входа

Все точки входа для каждого файла приходят в `InteractiveFileRenamer.analyze_and_rename`. Отличаются дефолтами.

| Вход | Папка | Шаблон | Модель | Контекст (символы) | Параллельно | Перед переименованием |
|---|---|---|---|---|---|---|
| `ollama-rename` (без `-a`) | `-d`, иначе спрашивает; Enter = текущая папка | `--prefix`/`--ext` (второй — по умолчанию), иначе меню топ-5; Enter = самый частый | `-m`, иначе меню установленных; Enter = первая | `-c`, иначе спрашивает; Enter = 2048, не больше, чем вмещает `context_length` модели | `-p`, по умолчанию 0 → 1 | список файлов (первые 20), затем `Rename N files? [y/N]`; переименует только y/yes/д/да |
| `ollama-rename -a -d DIR` | `-d` (обязателен) | `--prefix new`, `--ext .txt` | `-m`, по умолчанию `qwen2.5-coder:7b` | `-c`, по умолчанию 2048 | `-p`, по умолчанию 0 → 1 | ничего, стартует сразу |
| `ollama-rename gui` | папка последнего Scan (введённый путь учитывается только после Scan), в виде `~/…`; уходит с каждым запросом | первый найденный шаблон выбран; ввод в поле префикса или расширения переключает на простое «начинается с», пустое расширение — любое | список установленных, выбрана первая | всегда 2048 | 1 (цикл в JS) | показан список; правка поля <250 мс до Rename переименует старый список; отложенное превью отменяется |

Module: `__main__`, `rename_files`, `app`

## Шаги

### 1. Развилка

Решает: CLI или GUI.
Ветки:
- `argv[1] == "gui"` → `app.run(argv[2:])`; Ctrl+C глушится;
- всё остальное → `rename_files.run(argv[1:])`.
stdout переключается на `errors="replace"`, чтобы старые кодовые страницы Windows печатали любое имя файла.
Module: `__main__`

### 2. Настройка

Решает: папку, префикс, расширение, модель, длину контекста.
Ветки:
- CLI `-a` → берёт флаги как есть; `-a` без `-d` → ошибка argparse;
- CLI без `-a` → спрашивает только то, чего нет в опциях: `-d` убирает вопрос о папке, `--prefix` или `--ext` — о шаблоне, `-m` — о модели, `-c` — о контексте;
- GUI → состояния на сервере нет: `/set_directory` проверяет папку и ищет шаблоны; каждый `/preview` и `/rename_file` несёт `directory` и ещё префикс/расширение или модель.
Без Ollama: CLI пишет «No Ollama models found. Using default model qwen2.5-coder:7b», у вопроса о контексте нет верхней границы; GUI выключает список моделей и кнопку Rename.
Сбой: CLI переспрашивает при неверном вводе; неверный `-d` без `-a` → в лог, выход 1 (если заданы `--prefix`/`--ext` — только после вопросов о модели и контексте). GUI: нет `directory`, пустой или не папка → 400. CLI без ввода (stdin из pipe, без `-a`) → «No input to answer the questions. Run with -a -d DIR …», выход 1.
Module: `rename_files`, `app`

### 3. Поиск шаблонов

Решает: какие группы (префикс, расширение) предложить, топ-5 по числу файлов.
Вход: папка. Выход: `[((prefix, ext), count), …]`.
Префикс — ведущая серия букв, или цифр, или символов: `new2.txt` → `new`, `2024-notes.md` → `2024`, `newsletter.txt` → `newsletter`.
Ветки: только файлы; dot-файлы и имена на `_` ни с чем не совпадают и не считаются.
Сбой: не папка → `ValueError("Invalid directory")`; не читается → «Can't read <папка>: <причина>». CLI пишет это в лог и выходит с 1; GUI отвечает 400.
Module: `rename_files`

### 4. Отбор файлов

Решает: точный список файлов на переименование.
Правило: имя начинается с префикса (с учётом регистра) и `name.lower().endswith(ext.lower())`, сортировка по имени.
Расширение без точки получает её: `txt` → `.txt`, поэтому `notes.mytxt` не берётся.
Префикс как целое слово (выбранный шаблон и CLI): следующий символ не продолжает последнюю серию букв или цифр префикса, как на шаге 3: `new` берёт `new1.txt`, `new.txt`, `new note.txt`, но не `newsletter.txt`; `2024` пропускает `20240101.md`.
Проверяются только серии букв и цифр: префикс-символ `-` берёт и `--y.txt`, который поиск считает группой `--`.
Ветки:
- пустое расширение у выбранного шаблона или в CLI (`--ext ""`, Enter в «Write your pattern») → файлы без расширения: группа `new` (без расширения) берёт `new1`, но не `new4.txt`;
- поля GUI, введённые вручную (`as_discovered: false`) → простое «начинается с», пустое расширение — любое: `new` берёт `newsletter.txt`; оба пустые → все файлы папки; список превью это показывает;
- ничего не подошло → CLI пишет «No files found to rename.», печатает сводку из нулей и выходит с 0; GUI показывает «No files match».
Сбой: неверная папка → CLI логирует ошибку и выходит с 1.
Module: `rename_files`

### 5. Папка бэкапа

Решает: куда копируются оригиналы.
`backup_YYYYMMDD_HHMMSS/` внутри папки; суффикс `-1`, `-2`, если имя занято.
Ветки:
- CLI: создаётся один раз, когда шаг 4 нашёл ≥1 файл, до любого вызова модели;
- GUI: создаётся первым `/rename_file` прогона; JS возвращает её имя с каждым следующим файлом; имя, которое не является существующей папкой `backup_*` в папке запроса → 400 «Backup folder is missing».
Удаляется, если в неё не скопирован ни один оригинал: CLI — когда прогон кончился, в том числе по Ctrl+C; GUI — после каждого файла, который упал или сохранил своё имя.
Без Ollama: создаётся и удаляется.
Сбой: не создать (папка только для чтения) → «Can't create a backup folder in …»: CLI пишет это в лог и выходит с 1 до вызова модели; GUI отвечает 400, строка показывает сообщение.
Module: `rename_files`, `app`

### 6. Чтение содержимого

Решает: текст, который увидит модель.
Вход: путь к файлу, лимит в символах. Выход: строка, не длиннее лимита.
Ветки: по типу файла (см. таблицу развилок).
Пустой или пробельный текст → файл падает с «file is empty», как PDF без текста.
`-c` — целое число ≥ 1; иначе ошибка argparse до начала прогона.
Сбой: любое исключение (ошибки pypdf, декодирования, OSError) → этот файл падает с сообщением, прогон идёт дальше.
Module: `rename_files`

### 7. Запрос к модели

Решает: сырое предложенное имя.
`AsyncClient(timeout=300).generate(model, PROMPT_TEMPLATE, think=False, options={"num_predict": 128, "num_ctx": …})`. Хост из `OLLAMA_HOST`.
Промпт фиксирован и заточен под заметки разработчика: `<type> - <action> - <component> - <description>.<ext>`, нижний регистр, ≤128 символов.
`num_ctx` = (символы контекста + шаблон) / 2 символа на токен + 128, с округлением вверх до 1024, не меньше 4096: 2048 символов → 4096, 20000 → 11264. Одно значение на прогон, модель грузится один раз.
С `-c` и в GUI не ограничено обученной длиной модели; текст CJK (~1 символ на токен) всё ещё может обрезаться.
Без Ollama: каждый файл падает с «Ollama isn't reachable. Start it with `ollama serve` …».
Сбой: на файл, без повтора. Таймаут 300 с на чтение, столько может ждать Stop в GUI (`ollama list`/`show`: 10 с) → «Ollama didn't answer in 300 s …». 404 → «Model X isn't installed. Run `ollama pull X`.»; остальное → текст ошибки.
Module: `rename_files`

### 8. Очистка ответа
Решает: какая часть ответа — имя.
Убирает `<think>…</think>` (или незакрытый `<think>` до конца) и строки, начинающиеся с ```` ``` ````.
В каждой строке: побеждает фрагмент в `` `обратных кавычках` ``; уходят `*` и кавычки по краям, маркер списка (`1.`, `-`) и короткая метка (`File name:`).
Берёт первую строку с `-` или `.ext`, которая не кончается на `:`, `!` или `?` и где до первого дефиса не больше 3 слов, в нижнем регистре.
Ветки: такой строки нет («Sure!», голое `readme`) → файл падает с «model returned no file name».
«Here is a name for your file - hope it helps!» пропускается; `bug fix - update - auth - token refresh.md` берётся.
Module: `rename_files`

### 9. Санитайз
Решает: итоговое имя файла.
По порядку: убрать хвостовое `.ext`; удалить `` . ` ' , ; ``; заменить `< > / \ | ? * : " + % ! @` на `_`; пробелы → `-`; схлопнуть `--`; срезать не-словесные символы и `_` в начале; обрезать до `128 − len(suffix)` символов и до 255 байт вместе с суффиксом; срезать их в конце.
`_` рядом с `-` остаётся: `task - fix: api` → `task-fix_-api`.
Любая письменность и ведущие цифры остаются: `заметка - про - бэкап` → `заметка-про-бэкап`, `2024 - q3 - report` → `2024-q3-report`.
Первое правило снимает любой хвост `.\w+`: `release-notes-v2.0` → `release-notes-v2`.
Ветки: не осталось ни одной буквы (`""`, `123`) → `untitled-document-<8 hex>`.
Добавляет суффикс оригинала в его регистре.
Module: `rename_files`

### 10. Бэкап и переименование

Решает: свободное целевое имя; никогда не перезаписывает.
Идёт под одним `threading.Lock` на процесс, чтобы воркеры CLI и одновременные запросы GUI не взяли одно имя. Два процесса, переименовывающие в одной папке одновременно, всё ещё могут столкнуться.
Ветки:
- новое имя == старое → успех, без копии и переименования;
- иначе `copy2` в папку бэкапа (свободное имя), потом переименование в свободное имя (`-1`, `-2`, …).
Сбой: OSError → файл падает; его копия может уже лежать в бэкапе; оригинал на месте.
Module: `rename_files`

### 11. Цикл и отчёт

Решает: порядок, параллельность и что видит пользователь.
Ветки:
- CLI без `-a`: сначала показывает список файлов и спрашивает `Rename N files? [y/N]`; не «да» → «Nothing renamed.», выход 0;
- CLI: `asyncio.gather` по всем файлам с `Semaphore(max(-p, 1))`; прогресс каждые 10 файлов; печатает итоги и каждый упавший файл с причиной; код выхода 0, даже если файлы упали;
- GUI: JS шлёт по одному `/rename_file` на строку, по порядку; Stop срабатывает после текущего файла; в статусе — счётчики и папка бэкапа; после прогона шаблоны ищутся заново, список переименованных остаётся на экране.
Ctrl+C в CLI печатает «Operation interrupted by user.» без сводки; уже переименованные файлы остаются.
Module: `rename_files`, `app`, `static/script.js`

### Результат

Переименованные файлы в той же папке, оригиналы в `backup_<timestamp>/`.
CLI: «Renaming Operation Summary» со счётчиками обработано / переименовано / упало и причинами.
GUI: каждая строка показывает `old → new` или ошибку; статус «Renamed N files, M failed. Originals are in backup_…».
Module: `rename_files`, `static/script.js`

## Побочные потоки

### Запуск сервера GUI

`ollama-rename gui [--port N] [--browser]`. Порт: `--port`, иначе `FILE_RENAMER_PORT`, иначе 5000. Вне 1–65535 → ошибка argparse.
Порт занят → `GET /health`: чужое приложение → следующий свободный в пределах 50; File Renamer → «Restart it? [y/N]» (без TTY — No) → SIGTERM и ожидание до 5 с, или оставить старый и выйти. Нет свободного порта или старый экземпляр держит порт дольше 5 с → «Can't start File Renamer: …», выход 1.
`--browser` → только сервер и ссылка. Linux без `qtpy` или `gi` → браузер по умолчанию. Иначе окно pywebview; закрытие окна гасит сервер.
Module: `app`

### Защита запросов GUI

Любой запрос с Host не `127.0.0.1` и не `localhost` → 403 (DNS rebinding). Сервер слушает только 127.0.0.1.
`/rename_file` принимает только голое имя существующего файла в папке, названной в запросе; что-то с путём → 400.
Межсайтовая form-POST не может прислать JSON, получает 400 и ничего не меняет.
Питает: шаги 2, 5, 10.
Module: `app`

### Список моделей

`GET /models` и меню CLI зовут `ollama list`; при любой ошибке логируют её и возвращают пустой список.
Питает: шаг 2.
Module: `rename_files`, `app`
